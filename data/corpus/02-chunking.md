# 分块策略：固定窗口、递归、结构感知与语义分块

分块（chunking）决定检索的最小语义单元，是 RAG 里最容易被低估、却对召回质量影响最大的一步。它同时约束三件事：**检索粒度**（块越小，向量越聚焦）、**上下文完整性**（块越大，指代与条件越齐全）、**生成预算**（块越大，塞进提示词的 token 越多）。任何分块方案都是这三者之间的取舍。

## 一、四种主流分块策略

### 1. 固定窗口分块（Fixed-size）

按 token 数硬切，配合重叠窗口。典型配置是 `chunk_size=512`、`chunk_overlap=128`（即 25% 重叠）。它实现最简单、块长度方差为 0，便于批处理与缓存；缺点是会从句子中间切断，且不尊重标题与代码块边界。适合日志、聊天记录这类弱结构文本。

### 2. 递归分块（Recursive Character Splitting）

按优先级依次尝试分隔符：段落 `\n\n` → 换行 `\n` → 句号 `。`/`.` → 空格 → 字符。若某段仍超过 `chunk_size` 则递归下降一级，否则合并相邻小段直至接近上限。这是大多数默认方案的基线，兼顾了"尽量贴边界"与"长度可控"。

### 3. 结构感知分块（Structure-aware）

利用 Markdown 标题层级、HTML 标签、PDF 版面或代码函数签名切分。对技术文档而言，**按 `##` 小节切块**通常显著优于定长切块，因为它天然保证了"一个小节讲一件事"。常见做法是：

- 以 Markdown 标题为一级边界，表格、代码块、公式视为原子单元不拆分；
- 在块前拼接"面包屑"元数据，如 `文档标题 > 二级标题 > 三级标题`，让脱离原文的块仍有语境；
- 过长的表格按表头 + N 行切片，并在每片重复表头。

### 4. 语义分块（Semantic Chunking）

对句子或小段落编码，计算相邻句向量余弦相似度；当相似度跌破阈值（例如 $< 0.6$）或跌幅超过滑动窗口均值的一个标准差时切分。也可用"潜在语义"变体（如 TextTiling、基于 perplexity 的断点检测）。语义分块能避免话题漂移，但成本高、切分结果不稳定，且对短文档收益不明显。

## 二、边界之外：上下文增强

块切得再准，脱离原文后仍会丢失指代对象。三种常用补偿手段：

- **句子窗口检索（sentence-window retrieval）**：以句子为检索单元，命中后向前后各扩 1～2 句再送入生成。
- **父子分块（small-to-big / parent-child）**：用小块（如 256 token）做检索提高命中率，用其父块（如 1024 token）做生成提高完整性。
- **上下文前缀（contextual header）**：为每个块生成一句"该块在讲什么"的摘要或文档路径前缀一起编码。这类前缀能明显改善孤立块的向量质量。

## 三、参数怎么选：从评测倒推

| 参数 | 常见取值 | 影响 |
| --- | --- | --- |
| chunk_size | 256 / 512 / 1024 token | 越小召回越准、上下文越碎 |
| chunk_overlap | 10%～25%（如 128） | 缓解边界信息丢失，增大索引体积 |
| 每文档块数 | 5～50 | 影响 top_k 下的文档级多样性 |
| top_k | 5～20 | 与重排配合时，召回可放宽到 20～50 |

检索指标对 chunk_size 的敏感度通常高于对嵌入模型的敏感度：在技术问答集上，`chunk_size` 从 1024 降到 512 常能带来 Recall@5 的明显提升；继续降到 256 则开始因上下文缺失而拖累答案忠实度。因此推荐的调参流程是：

1. 固定嵌入模型与 BM25 参数，扫 `chunk_size ∈ {256, 512, 1024}`，看 Recall@5 与 nDCG@10；
2. 选出最优区间后再扫 `overlap ∈ {0, 64, 128, 256}`，观察是否出现边际收益递减；
3. 最后引入重排与融合，检验分块收益是否被重排"吃掉"——若重排后差距收敛，说明分块已不是瓶颈。

## 四、工程细节与常见坑

- **元数据必须一块带上**：`doc_id`、`chunk_id`、标题路径、原始字符偏移。引用回溯与高亮都依赖它们；常用的 `chunk_id` 形式是 `{doc_id}#{序号}`。
- **不要跨文档合块**：合并不同 `doc_id` 的碎片会让引用无法归属。
- **表格与代码单独处理**：把表格行序列化成 `列名: 值` 的键值文本，比直接投喂 Markdown 表格更利于嵌入模型理解。
- **去重与近重复**：重叠窗口会产生近似重复块，检索时需按相似度阈值做去重，避免 top_k 被同一段文字占满。
- **分块与检索方式要匹配**：BM25 受益于保留完整术语（`k1`、`b` 这类参数名），语义分块若把术语切开反而损害关键词召回，因此混合检索系统里更常见的组合是"结构感知切块 + 混合召回"。
