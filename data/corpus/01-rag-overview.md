# RAG 是什么：从 Naive RAG 到 Advanced RAG

检索增强生成（Retrieval-Augmented Generation，RAG）把"参数化记忆"（大语言模型的权重）与"非参数化记忆"（外部语料库）拼在一条推理链上：先用检索器从知识库中取回与问题相关的片段，再把这些片段作为上下文交给生成模型组织答案。它针对的是大模型的三类固有缺陷：知识截止（knowledge cutoff）、幻觉（hallucination）以及无法追溯出处。RAG 的核心承诺是**把"记住事实"的责任从模型权重转移到可更新、可审计的索引上**。

## 一、Naive RAG 的标准四段式流水线

朴素 RAG 的链路可以写成四个阶段：

1. **Index（离线索引）**：文档解析 → 清洗 → 分块（chunking）→ 向量化（embedding）→ 写入向量库与倒排索引。
2. **Retrieve（检索）**：把用户问题编码为查询向量，做近似最近邻（ANN）搜索，通常取 top_k=5～20 个候选块。
3. **Rerank（可选重排）**：用交叉编码器（Cross-Encoder）对候选做精排，取前 3～5 条。
4. **Generate（生成）**：把片段拼接成提示词，要求模型"仅依据给定资料回答，并标注引用编号"。

形式上，生成目标是在给定问题 $q$ 与检索集合 $\mathcal{D}_q$ 的条件下最大化似然：

$$P(a \mid q) = \sum_{d \in \mathcal{D}_q} P(d \mid q)\, P(a \mid q, d)$$

朴素实现在工程上通常简化成"检索一次、拼接一次、生成一次"，$\mathcal{D}_q$ 只取一轮。

## 二、Naive RAG 的七个典型失败模式

- **召回缺失**：正确片段根本没进 top_k，后续再怎么重排也无济于事。
- **粒度错配**：块太短则指代消解失败（"它的参数"没有先行词），块太长则噪声淹没信号。
- **查询-文档语义鸿沟**：用户口语化提问与文档书面表述的向量距离过大，可用 HyDE（先让模型生成假想答案再检索）缓解。
- **多跳断裂**：问题需要串联两条以上事实（例如"某方法的默认参数是什么，它在另一篇里的评测结论如何"），单轮检索只能覆盖一跳。
- **上下文噪声**：塞入过多不相关块会显著拉低精确率，造成"迷失在中间"（lost in the middle）现象。
- **引用不可信**：模型给出 `[1]` 标记但该标记与陈述不符，即引用准确率（citation precision）偏低。
- **无答案时硬答**：检索结果与问题无关时仍强行生成，而不是拒答（refusal）。

## 三、Advanced RAG 的三条改造主线

Advanced RAG 的改进几乎都能归入"检索前 / 检索中 / 检索后"三处：

| 阶段 | 代表技术 | 主要收益 |
| --- | --- | --- |
| 检索前 Pre-Retrieval | 查询改写（query rewriting）、HyDE、查询分解、元数据过滤 | 缩小语义鸿沟，提升召回 |
| 检索中 Retrieval | 混合检索（向量 + BM25）、RRF 融合、多路召回 | 兼顾语义泛化与关键词精确匹配 |
| 检索后 Post-Retrieval | Cross-Encoder 重排、上下文压缩、去重与重排序 | 提升 nDCG@10 与上下文信噪比 |

其中"向量召回 + 关键词召回"的互补性来自两种打分机制的差异：稠密向量擅长同义改写，BM25 擅长稀有实体、编号与专有名词的精确命中。二者用 RRF（Reciprocal Rank Fusion，倒数排名融合）合并时，$k=60$ 是一个被广泛沿用的经验常数。

## 四、评测视角：RAG 必须分阶段度量

端到端答对率不足以定位问题。工程上通常把指标拆成两层：

- **检索层**：Recall@k（如 Recall@5）、MRR、nDCG@10，用于判断上下文里有没有答案。
- **生成层**：忠实度（faithfulness）、引用准确率、拒答正确率，用于判断答案有没有超出资料。

一个常见诊断结论是"Recall@5 高但答案仍错"，这通常说明问题出在生成阶段（提示词、上下文顺序或模型能力），而非检索器——此时继续调分块与嵌入模型收益有限。

## 五、与微调、长上下文的取舍

- **RAG vs 微调**：RAG 适合频繁变动的事实型知识，改动只需重建索引；微调适合稳定的风格、格式与领域推理模式。二者可叠加使用。
- **RAG vs 长上下文**：把整库塞进 128k 窗口成本高且受"中间遗失"影响；分块检索在同等预算下往往更便宜、更可解释。
- **代价**：RAG 引入了索引新鲜度、分块策略、重排延迟等新的运维面，链路上每多一个组件（改写、重排、多跳迭代），端到端 P95 延迟都会叠加。
