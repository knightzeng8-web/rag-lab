# 重排与评测：Recall@k、MRR、nDCG 与引用准确率

"先宽召回、再精排序"是 RAG 检索环节的标准分工：召回阶段（向量、BM25 或二者融合）负责把答案块放进候选集，重排阶段负责把最该看的块顶到最前面。二者目标不同——召回优化的是**上界**，重排优化的是**顺序**——因此必须用不同指标分别度量。

## 一、重排：Cross-Encoder 与双编码器的分工

- **双编码器（Bi-Encoder）**：查询与文档各自独立编码，可离线预计算文档向量，用 ANN 实现毫秒级检索；代价是查询与文档之间没有细粒度交互，精度受限。
- **交叉编码器（Cross-Encoder）**：把 `[query, passage]` 拼成一个序列送入 Transformer，输出单一相关性分数。因为有完整的注意力交互，判别力显著更强，但无法预计算，复杂度为 $O(n)$ 次前向——只能对少量候选使用。

因此标准流水线是：ANN 召回 top 20～50 → Cross-Encoder 精排 → 取 top 3～5 送入生成。常见重排模型包括 `bge-reranker-base/large`、`bge-reranker-v2-m3`、Cohere Rerank 等；离线可用小型（约 100M 参数级）模型，量级上单条候选的推理通常在几毫秒到几十毫秒。

工程注意点：

- **候选宽度**：召回只给 5 条，重排几乎没有提升空间；给到 50 条则 nDCG@10 通常明显上升，但延迟线性增长。
- **分数可比性**：Cross-Encoder 输出是未归一化的 logit，跨查询不可比，不要拿它做固定阈值过滤；需要阈值时应先做 sigmoid 或分位数校准。
- **延迟预算**：重排是端到端延迟中最易失控的一环，常见做法是对低置信或无需精排的查询跳过重排（此时延迟分解里的 rerank 阶段应为 0.0ms）。
- **蒸馏**：把 Cross-Encoder 的排序结果蒸馏回双编码器，可在保持 ANN 速度的前提下拿到部分重排收益。

## 二、检索指标：定义与用法

设 $k$ 为截断位置，$\text{rel}(i)$ 表示第 $i$ 位文档是否相关，$\text{rank}$ 为第一个相关文档的名次。

- **Recall@k**：top_k 中相关文档数 / 全部相关文档数。衡量"答案有没有被取回"，是 RAG 最该先看的指标；典型门槛是 Recall@5 ≥ 0.8。
- **Precision@k**：top_k 中相关文档占比。块越碎该指标越低，单看不具指导性。
- **MRR（Mean Reciprocal Rank）**：只关心第一个相关结果，$\text{MRR}=\frac{1}{|Q|}\sum_{q}\frac{1}{\text{rank}_q}$。适合"一问一答、只需一条正确证据"的场景。
- **nDCG@k**：带位置折损的排序质量，$\text{DCG}_k=\sum_{i=1}^{k}\frac{2^{\text{rel}_i}-1}{\log_2(i+1)}$，再除以理想排序的 IDCG 归一到 [0,1]。它同时惩罚"相关文档排太靠后"和"无关文档插在前面"，是衡量重排收益的首选。nDCG@10 是常见报告口径。
- **MAP@k**：对所有相关文档位置取平均，关注整体排序而非首位。

一句话记忆：**Recall@k 看覆盖，MRR 看首条，nDCG@10 看整体顺序。**

## 三、端到端指标：生成层怎么评

- **忠实度 / Groundedness**：答案中的每个断言是否能被引用片段支持，常用 LLM-as-judge 或 NLI 模型打分。
- **引用准确率（Citation Precision / Accuracy）**：`[n]` 标记所指的块是否真的支撑该句。引用编号错位比"没有引用"危害更大，因为它制造虚假可追溯性。
- **拒答正确率**：对不可回答的问题（语料里没有答案）应输出拒答。该指标与召回指标存在张力——召回越激进，越容易把无关块喂给模型从而诱发硬答。
- **答案正确率（EM / F1 / 语义相似度）**：与参考答案对比，但需注意参考答案本身可能不唯一。

## 四、评测集的构造与常见偏差

一个可用的评测集应有区分度：覆盖 factual（事实查找）、comparison（跨文档对比）、multihop（需两跳以上证据）、unanswerable（应拒答）四类，并标注 difficulty。每条记录至少包含 `question`、`gold_doc_ids`、`gold_answer`、`type`、`difficulty`；`gold_doc_ids` 用文档级标注即可支撑文档级召回评测，块级评测则需额外标注 chunk。

常见偏差与陷阱：

- **单跳偏置**：绝大多数问题可由一个块回答，导致多跳能力被高估。
- **标注泄漏**：参考答案照抄原文，使语义相似度虚高。
- **位置偏置**：LLM 评委偏好靠前的上下文，评测时应随机打乱候选顺序。
- **指标串味**：用 nDCG@10 的改进去证明生成质量提升是不成立的——必须回到忠实度与引用准确率。

## 五、融合收益与重排收益的混淆

评测混合检索（向量 + BM25 + RRF，$k=60$）时，必须做三行消融：vector-only、bm25-only、fused。常见结论是融合把 Recall@5 提高了 3～10 个点，但一旦接上 Cross-Encoder，三行之间的差距会大幅收敛——这说明重排已经在弥补召回顺序的缺陷。反之，如果重排后 Recall@5 出现下降，几乎总是因为候选窗口取太窄，把正确答案挤出了精排列表。

## 六、延迟与成本的三角取舍

检索质量的每一次提升通常伴随延迟：放宽 top_k → ANN 更慢；加重排 → 每候选一次前向；加查询改写 → 多一次 LLM 调用。因此评测报告里应把指标与延迟分解（rewrite / retrieve / rerank / generate / total）一并给出，只报质量不报延迟的方案在线上不可用。
